1. MCP(Model Context Protocol)란 무엇인가요?

MCP(Model Context Protocol, 모델 컨텍스트 프로토콜)는 한 문장으로 요약하면 "인공지능(LLM)이 세상 밖의 데이터나 도구와 대화할 때 사용하는 세계 공통 표준 규격(AI계의 USB-C 포트)"입니다.

단어가 조금 어렵게 느껴지시나요? 세 단어를 하나씩 뜯어보면 아주 쉽습니다!

  • Model (모델): 우리가 사용하는 gemini-3.8-flash, ChatGPT, Claude 같은 AI 두뇌를 뜻합니다.
  • Context (컨텍스트 / 맥락·정보): AI가 대답을 잘하기 위해 참고해야 할 외부 정보와 도구(내 컴퓨터의 메모장 파일, 오늘의 일기, 실시간 인터넷 검색 결과, 회사 데이터베이스 등)를 뜻합니다.
  • Protocol (프로토콜 / 약속·규격): AI 두뇌와 외부 도구가 서로 헷갈리지 않고 데이터를 주고받기 위해 정해둔 공통의 대화 규칙(연결 단자 규격)입니다.

🤔 왜 MCP가 필요하게 되었을까요? ("방 안에 갇힌 천재" 이야기)

Gemini나 GPT 같은 대규모 언어 모델(LLM)은 세상 모든 지식을 공부한 천재 학자와 같습니다. 하지만 이 천재에게는 치명적인 약점이 하나 있습니다. 바로 아무것도 없는 방 안에 혼자 갇혀 있다는 점입니다!

그래서 AI에게 "내 컴퓨터 바탕화면에 있는 my_info.txt 파일을 읽어서 요약해 줘"라고 시키면, 기본 AI는 "저는 당신의 컴퓨터 파일을 열 수 있는 손이 없습니다"라고 대답합니다. AI에게 파일을 읽는 손과 인터넷을 검색하는 발을 달아주어야 비로소 'AI 에이전트'가 됩니다.

🔌 일상 비유: 옛날 휴대폰 충전기 대혼란 vs USB-C 천하통일

• 과거 (MCP가 없던 시절): 옛날에는 삼성폰, LG폰, 아이폰, 디지털카메라마다 충전기 구멍 모양이 전부 달랐습니다. AI 세상도 똑같아서, Gemini에 '내 파일 읽기'를 연결하는 코드와 Claude에 '내 파일 읽기'를 연결하는 코드를 각각 따로 짜야만 했습니다.
• 현재 (MCP가 등장한 이후): 이제 모든 기기가 USB-C 단자 하나로 통일되었듯, '내 파일 읽기 도구'를 MCP 규격(MCP 서버)으로 딱 한 번만 만들어 두면, Gemini든 Claude든 GPT든 선만 꽂아서 그대로 가져다 쓸 수 있게 되었습니다!

2. MCP의 전체 구조와 서버 안의 '3가지 보물상자'

MCP 시스템을 만들 때는 항상 클라이언트(client.py)와 서버(server.py) 두 편으로 나누어 작성합니다. 왜 굳이 파일 두 개로 나눌까요?

노트북 본체(클라이언트)와 외장하드(서버)가 분리되어 있어야, 외장하드를 다른 노트북에도 꽂아서 쓸 수 있기 때문입니다! 아래 그림을 통해 각 역할을 살펴봅시다.

🖼️ [그림 2] MCP 클라이언트(client.py)와 MCP 서버(server.py)의 내부 구조도
🛠️

보물 1: 도구 (@mcp.tool)

"AI의 손과 발"
파이썬 함수 위에 @mcp.tool() 스티커만 붙이면, AI가 필요할 때 스스로 호출할 수 있는 도구가 됩니다. 이때 함수 아래에 적는 설명글(독스트링 """...""")이 곧 AI가 읽는 도구 사용설명서가 됩니다!

📜

보물 2: 프롬프트 (@mcp.prompt)

"미리 준비된 모범 대본"
매번 클라이언트에서 긴 지시사항을 적을 필요 없이, 서버에 @mcp.prompt()로 모범 대본을 저장해 두고 첫 대화 때 불러올 수 있습니다.

🔌

MCP 클라이언트 (ClientSession)

"도구 배달부"
서버에 접속해 load_mcp_tools()로 도구들을 싹 긁어모은 뒤, 랭그래프 에이전트(create_agent)의 손에 쥐여주는 역할을 합니다.

🎛️

멀티허브 (MultiServerMCPClient)

"USB-C 멀티탭"
실습 2에서 사용하며, 내 컴퓨터의 파일 서버와 인터넷의 웹 검색 서버를 동시에 꽂아 여러 에이전트가 나눠 쓰게 해줍니다.

사용자가 질문을 던졌을 때, 클라이언트(client.py)와 서버(server.py) 사이에서 실제로 무슨 일이 일어나는지 4단계 만화처럼 따라가 볼까요?

🖼️ [그림 3] 사용자 질문부터 도구 실행까지 MCP의 4단계 대화 과정

📡 알아두면 끝! MCP의 2가지 연결 방식 (stdio vs streamable_http)

코드에서 transport="stdio" 또는 transport="streamable_http"라는 표현이 등장합니다. 이 둘은 "클라이언트와 서버가 어디에 있느냐"에 따라 고르는 연결선 종류일 뿐입니다!

연결 방식 (Transport) 일상 비유 언제 사용하나요? 챕터 9 코드 예시
1. stdio
(Standard Input/Output)		 🔌 내 컴퓨터에 직접 꽂는 유선 USB 케이블 MCP 서버 파일(server.py)이 내 컴퓨터 안에 있을 때 사용합니다. 클라이언트가 자동으로 서버 파이썬 파일을 켜서 대화합니다. • 실습 1: 개인 비서 & 일기장 서버
• 실습 2: 로컬 파일 탐색 서버
2. streamable_http
(HTTP 네트워크 통신)		 📶 인터넷으로 연결하는 무선 Wi-Fi MCP 서버가 내 컴퓨터가 아니라 외부 인터넷 주소(https://...)에서 돌아가고 있을 때 사용합니다. • 실습 2: Tavily 실시간 웹 검색 원격 MCP 서버

1. [실습 1] 나만의 첫 MCP 서버 만들기 (@mcp.tool & @mcp.prompt)

FastMCP를 사용하면 일반 파이썬 함수 위에 데코레이터(@mcp.tool(), @mcp.prompt())만 붙여서 손쉽게 MCP 서버를 만들 수 있습니다.

📄 CHAP9_MCP/mcp_agent/server.py 핵심 구조 FastMCP 서버 
from mcp.server.fastmcp import FastMCP
from mcp.server.fastmcp.prompts import base

# [ 1 ] "MCPServer"라는 이름의 도구 상자(서버) 생성
mcp = FastMCP("MCPServer")

# [ 2 ] @mcp.tool(): 내 정보 파일(my_info.txt)을 읽는 도구 등록
@mcp.tool()
def read_user_info() -> str:
    """사용자의 정보를 담고 있는 txt 파일을 읽어옵니다."""
    ...

# @mcp.tool(): 대화 요약, 감정, 다짐을 받아 일기장 파일로 저장하는 도구 등록
@mcp.tool()
def save_diary(conversation_summary: str, emotion: str, resolution: str) -> dict:
    """일기 형태로 텍스트 파일을 저장합니다."""
    ...

# @mcp.prompt(): 자주 쓰는 '친절한 개인 비서 매뉴얼 대본'을 서버에 미리 저장
@mcp.prompt()
def default_prompt(message: str) -> list[base.Message]:
    return [base.AssistantMessage("당신은 따뜻하고 공감 능력이 뛰어난 개인 비서입니다..."), base.UserMessage(message)]

if __name__ == "__main__":
    mcp.run(transport="stdio")
파일: CHAP9_MCP/mcp_agent/client.py

2. [실습 1] MCP 클라이언트로 서버 도구와 프롬프트 불러오기

client.py에서는 StdioServerParameters로 방금 만든 server.py를 실행해 연결하고, 서버 안의 도구(load_mcp_tools)와 프롬프트(load_mcp_prompt)를 꺼내 gemini-3.8-flash 에이전트에게 장착합니다.

📄 CHAP9_MCP/mcp_agent/client.py 핵심 구조 gemini-3.8-flash 
model = ChatGoogleGenerativeAI(model="gemini-3.8-flash")

# 현재 가상환경의 파이썬(sys.executable)으로 같은 폴더의 server.py를 실행하도록 설정
SERVER_SCRIPT = str(Path(__file__).resolve().parent / "server.py")
server_params = StdioServerParameters(command=sys.executable, args=[SERVER_SCRIPT])

async with stdio_client(server_params) as (read, write):
    async with ClientSession(read, write) as session:
        await session.initialize()

        # [ 1 ] 서버의 모든 @mcp.tool()을 랭체인 도구로 변환!
        tools = await load_mcp_tools(session)
        # [ 2 ] 모델 + MCP 도구 + 단기 메모리(InMemorySaver)로 에이전트 완성!
        agent = create_agent(model, tools, checkpointer=InMemorySaver())

3. [실습 2] 로컬 파일 탐색 전용 MCP 서버 (FileSearch)

두 번째 실습에서는 내 컴퓨터의 폴더 목록을 보거나(file_listup), 파일의 상세 속성·본문을 읽고(file_info), 요약본을 마크다운 파일로 저장하는(save_file) 3가지 비동기(async def) 도구를 담은 MCP 서버를 만듭니다.

MCP 도구 이름 입력 인자 하는 일 (역할)
file_listup directory: str 지정한 폴더 안에 있는 파일/폴더 이름 목록을 리스트로 반환합니다.
file_info path: str 파일의 크기, 생성/수정 시각, 권한, 그리고 파일 안의 텍스트 본문을 읽어 반환합니다.
save_file content: str, output_path: str 정리된 텍스트 내용을 지정된 파일(기본값: file_info.md)로 저장합니다.
파일: CHAP9_MCP/mcp_multi_agent/client.py

4. [실습 2] 멀티 MCP 서버(MultiServerMCPClient)와 슈퍼바이저 아키텍처

📄 MultiServerMCPClient 멀티허브 설정 코드 HTTP + stdio 동시 연결 
client = MultiServerMCPClient({
    # [ 1 ] 인터넷 원격 Tavily 웹 검색 MCP 서버 (streamable_http 방식)
    "tavily": {
        "url": f"https://mcp.tavily.com/mcp/?tavilyApiKey={TAVILY_API_KEY}",
        "transport": "streamable_http",
    },
    # [ 2 ] 내 컴퓨터 로컬 파일 검색 MCP 서버 (stdio 방식)
    "file": {
        "transport": "stdio",
        "command": sys.executable,
        "args": ["./server.py"],
    }
})

# 서버 이름별로 도구를 깔끔하게 분리해서 각 담당 에이전트에게 배분!
tavily_tools = await client.get_tools(server_name="tavily")
file_tools = await client.get_tools(server_name="file")
