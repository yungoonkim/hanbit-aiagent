시작하기 전에: 단기 기억 vs 장기 기억 한눈에 비교하기

사람도 방금 들은 전화번호를 외우는 단기 기억과 내 단골 메뉴나 어릴 적 추억을 기억하는 장기 기억이 따로 있듯, 랭그래프 에이전트도 두 가지 기억 장치를 나누어 사용합니다.

💡 일상 비유: 콜센터 오늘 통화 메모지 vs 단골 미용실 고객 수첩

• 단기 메모리 (InMemorySaver + thread_id) = 상담원이 오늘 이번 통화 중에만 적어두는 일회용 통화 메모지입니다. 통화 방(thread_id)이 바뀌면 이전 통화 내용은 보이지 않습니다.
• 장기 메모리 (InMemoryStore + user_id) = 단골 미용실 원장님이 손님 이름(user_id)별로 취향, 목표, 고민을 적어두는 평생 단골 수첩입니다. 다음 달에 새 통화(thread_id="2")로 찾아와도 수첩을 펼쳐 기억해 냅니다!

구분 단기 메모리 (Short-term Memory) 장기 메모리 (Long-term Memory)
일상 비유 📞 이번 통화에서만 쓰는 통화 메모지 📒 몇 달 뒤에도 펼쳐보는 단골손님 평생 수첩
핵심 클래스 InMemorySaver() (체크포인터) InMemoryStore() (스토어 저장소)
구분 기준 키 thread_id (대화방 번호 기준) namespace 예: (user_id, category)
기억 범위 현재 대화방(thread_id) 안에서만 유지 대화방이 바뀌어도(thread_id="1" → "2") 영구 공유
파일: CHAP8_memory/short-term memory.ipynb (8.2절)

1. 챗봇에 단기 메모리(InMemorySaver) 적용하기

기본 LLM(gemini-3.8-flash)은 한 번 대답하고 나면 방금 무슨 대화를 했는지 즉시 잊어버립니다. 그래프를 컴파일할 때 checkpointer=InMemorySaver()를 달아주면 대화방 번호(thread_id)별로 상태를 차곡차곡 기억합니다.

📄 8.2.2절 단기 메모리 챗봇 핵심 코드 InMemorySaver 
from langgraph.graph import StateGraph
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import InMemorySaver
from langchain_google_genai import ChatGoogleGenerativeAI

# [ 1 ] 대화 기록을 차곡차곡 쌓는(add_messages) 상태 정의
class State(TypedDict):
    messages: Annotated[list, add_messages]

# [ 2 ] gemini-3.8-flash 모델 준비
llm = ChatGoogleGenerativeAI(model="gemini-3.8-flash")

# [ 3 ] 단기 기억 장치(InMemorySaver)를 연결해 그래프 컴파일!
checkpointer = InMemorySaver()
graph = graph_builder.compile(checkpointer=checkpointer)

# 같은 thread_id("1")로 부르면 방금 말한 이름을 정확히 기억합니다!
graph.invoke({"messages": [{"role": "user", "content": "제 이름은 공원나연입니다."}]}, {"configurable": {"thread_id": "1"}})
graph.invoke({"messages": [{"role": "user", "content": "제 이름이 뭐라고요?"}]}, {"configurable": {"thread_id": "1"}})
파일: CHAP8_memory/short-term memory.ipynb (8.3.1절)

2. 단기 메모리 관리법 ①: 메시지 트리밍 (trim_messages)

대화가 100마디, 1000마디로 길어지면 AI에게 매번 전체 대화를 다 보낼 때 요금(토큰 비용)이 폭발하고 응답 속도도 느려집니다. 가장 간단한 해결책은 가위로 최근 대화 몇 마디만 남기고 앞부분을 잘라내는 것(trim_messages)입니다.

✂️ 트리밍(Trimming)의 장점과 한계

• 장점: 추가 AI 호출 없이 글자 수(토큰 수)만 계산해 즉시 잘라내므로 매우 빠르고 경제적입니다.
• 한계: max_tokens=128처럼 작게 자르면, 대화 맨 처음에 말했던 "저는 AI를 공부하는 학생입니다"라는 정보가 잘려 나가서 나중에 물어보면 기억하지 못합니다.

📄 8.3.1절 trim_messages 설정 방법 토큰 절약 
messages = trim_messages(
    state["messages"],
    strategy="last",                         # 가장 최근(마지막) 메시지부터 남김
    token_counter=count_tokens_approximately, # 대략적인 토큰 수 계산기
    max_tokens=128,                          # 최대 128토큰까지만 허용
    start_on="human",                        # 잘린 뒤 첫 메시지는 반드시 사람 질문으로 시작
    end_on=("human", "tool"),              # 마지막 메시지는 사람 질문 또는 도구 결과로 끝남
)
파일: CHAP8_memory/short-term memory.ipynb (8.3.2절)

4. 장기 메모리(InMemoryStore)와 시맨틱(의미) 검색

장기 메모리는 컴퓨터 폴더처럼 네임스페이스(namespace 튜플)와 고유 키(key)로 데이터를 체계적으로 분류해 저장합니다. 여기에 임베딩 모델을 연결하면 단어가 정확히 일치하지 않아도 뜻이 비슷한 기억을 찾아내는 시맨틱 검색(store.search)이 가능해집니다.

📁

1. 네임스페이스 (Namespace)

"서랍장 폴더 경로"
("user_123", "goals")처럼 사용자 ID와 카테고리를 묶어 방을 나눕니다.

📥

2. 저장하기 (store.put)

"수첩에 메모 꽂기"
지정한 폴더(namespace)와 번호(key)로 새로운 기억을 저장합니다.

🔍

3. 의미 검색 (store.search)

"비슷한 뜻 찾아내기"
query="운동"으로 검색하면 "주 3회 운동", "5kg 감량"을 똑똑하게 찾아옵니다.

파일: CHAP8_memory/long-term memory.ipynb (8.4.2 ~ 8.4.5절)

5. [종합 실습] 단기+장기 기억을 모두 갖춘 라이프 코치 에이전트

라이프 코치 에이전트에게 3가지 메모리 도구(get_user_info, save_user_info, search_user_memories)를 쥐여주고, checkpointer(단기 기억)와 store(장기 기억)를 동시에 연결합니다.

📄 8.4.5절 라이프 코치 에이전트 생성 코드 gemini-3.8-flash 
model = init_chat_model("google_genai:gemini-3.8-flash")
checkpointer = InMemorySaver() # 오늘 통화 기억용 (단기)

agent = create_agent(
    model=model,
    tools=[get_user_info, save_user_info, search_user_memories],
    store=store,               # 단골손님 평생 수첩 연결 (장기)
    system_prompt="당신은 누적된 사용자 메모리를 활용하여 맞춤 조언을 제공하는 친절한 라이프 코치입니다...",
    checkpointer=checkpointer, # 현재 대화방 맥락 유지 (단기)
)
