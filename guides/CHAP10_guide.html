1. A2A(Agent-to-Agent) 프로토콜은 어떻게 나오게 되었을까요?

코드를 살펴보기 전에, 왜 2025년 봄 전 세계 IT 업계가 A2A(Agent2Agent) 프로토콜의 등장에 열광했는지 그 탄생 배경부터 이야기처럼 쉽게 알아봅시다.

① 에이전트 춘추전국시대와 '외딴섬(Silo)' 문제의 등장

2024~2025년을 거치며 수많은 기업들이 앞다투어 AI 에이전트를 도입했습니다. 그런데 막상 회사 안에서 에이전트를 써보니 예상치 못한 큰 벽에 부딪혔습니다.

예를 들어 한 회사 안에 다음과 같은 에이전트들이 있다고 상상해 보세요:

  • 재무팀 에이전트: 파이썬 LangGraph로 직접 개발한 예산 계산·일정 관리 에이전트
  • 마케팅팀 에이전트: 순수 MCP와 Tavily 검색 엔진을 연결해 만든 시장조사 에이전트
  • 인사/영업팀 에이전트: Workday, Salesforce, ServiceNow, SAP 같은 외부 클라우드 서비스에 내장된 에이전트

각 에이전트는 자기 분야에서는 똑똑한 전문가였지만, 만든 회사(벤더)나 개발 도구(프레임워크)가 다르다 보니 에이전트끼리 대화할 수 있는 '공통 언어'가 없었습니다! 결국 사람이 중간에서 이 에이전트의 답변을 복사(Ctrl+C)해서 저 에이전트에게 붙여넣기(Ctrl+V)하는 웃지 못할 상황이 벌어졌습니다. 업계에서는 이를 '에이전트 사일로(Agent Silo, 고립된 외딴섬) 현상'이라고 불렀습니다.

② 잠깐! 앞 장에서 배운 MCP로 에이전트끼리 연결하면 안 되나요?

여기서 아주 중요한 질문이 떠오릅니다. "9장에서 배운 MCP(Model Context Protocol)도 연결 표준이잖아요! 왜 MCP 말고 A2A가 새로 필요했나요?"

그 이유는 '수동적인 도구(Tool)'와 '자율적인 동료 에이전트(Agent)'는 본질적으로 완전히 다르기 때문입니다.

💡 왜 '동료 에이전트'는 단순한 '도구(MCP)'로 다룰 수 없을까요?

• 도구(Tool, MCP의 대상)는 전자레인지나 계산기 같습니다. 정해진 버튼(입력 변수 a=10, b=20)을 누르면 군말 없이 0.1초 만에 결과값을 내놓고 끝납니다. 스스로 생각하거나 되묻지 않습니다.
• 반면 동료 에이전트(Agent, A2A의 대상)는 외주 전문 업체나 타 부서 동료와 같습니다. 정해진 입력 칸 대신 자연어로 대화하며, 요청이 모호하면 "예산 한도가 얼마인가요?"라고 역질문(input_required)을 던지고, 며칠이 걸리는 큰 업무는 중간 진행 상황(working)을 보고하며, 무엇보다 자신의 내부 영업비밀(프롬프트·메모리·DB)을 외부에 공개하지 않은 채(블랙박스) 결과물만 납품해야 합니다!

③ 2025년 4월, 구글과 50개 이상의 글로벌 파트너가 손잡고 발표하다

바로 이 빈자리를 채우기 위해 2025년 4월 9일, 구글 클라우드 넥스트(Google Cloud Next '25) 행사에서 구글이 오픈소스 표준인 A2A(Agent2Agent) 프로토콜을 전격 발표했습니다. 특정 기업 혼자만의 규격이 되지 않도록 발표 첫날부터 LangChain, Salesforce, SAP, ServiceNow, Atlassian, Workday, PayPal, MongoDB, Cohere, Box, Intuit 등 50개 이상의 글로벌 소프트웨어 및 컨설팅 기업이 설계 파트너로 함께 참여했으며, 이후 리눅스 재단(Linux Foundation) 산하의 중립적인 오픈 표준 프로젝트로 기증되어 전 세계 에이전트들의 공용어로 자리 잡았습니다.

🏢 구글 공식 가이드 해설

2. 구글(Google)은 A2A를 어떻게 설명할까요?

구글 공식 개발자 블로그와 A2A 공식 문서에서는 비전공자도 단번에 이해할 수 있도록 '자동차 정비소(Auto Repair Shop)' 비유와 '5대 핵심 설계 원칙'으로 A2A를 설명합니다.

① 구글의 공식 비유: "자동차 정비소"로 이해하는 MCP와 A2A의 완벽한 분업

구글은 공식 문서에서 "A2A와 MCP는 경쟁자가 아니라, 함께 쓸 때 비로소 완성되는 짝꿍(Complementary Standards)"이라고 강조하며 다음과 같은 자동차 정비소 이야기를 들려줍니다.

🚗 구글 공식 문서의 '자동차 정비소' 비유

고장 난 자동차를 고치는 대규모 정비소를 생각해 봅시다.
• 🔌 MCP (에이전트 ↔ 공구 연결): 정비사 한 명이 작업대에서 유압 리프트(도구)를 올리고, 차량 스캐너(API)를 꽂고, 전동 렌치(함수)를 작동시키는 규격입니다. 즉, 작업자가 손에 공구를 쥐는 수직적 연결입니다.
• 🤝 A2A (에이전트 ↔ 에이전트 협업): 고객이 "차에서 덜컹거리는 소리가 나요"라고 말했을 때, 상담 매니저 에이전트가 엔진 정비사 에이전트에게 증상을 전달하며 진단을 요청하고("변속기 쪽 사진을 더 찍어 보내주세요"), 필요한 부품을 구하기 위해 외부 부품 공급사 에이전트에게 재고와 배송 일정을 협상해 발주서를 넣는 전문가들 사이의 수평적 대화 규격입니다!

📌 구글의 한 줄 요약: "도구(Tools)와 연결할 때는 MCP를 쓰고, 다른 에이전트(Agents)와 협업할 때는 A2A를 쓰세요!"

🖼️ 구글이 제시하는 큰 그림: 에이전트 간 수평 협업(A2A) + 도구 수직 연결(MCP)

② 구글이 발표한 A2A의 5대 핵심 설계 원칙 (5 Core Design Principles)

구글은 A2A 프로토콜을 설계할 때 다음 5가지 핵심 원칙을 세웠습니다. 이 5가지를 알면 왜 A2A 코드가 지금 같은 모양으로 만들어졌는지 단번에 이해됩니다!

🕵️

원칙 1. 자율적 에이전트 존중 (Opaque Agent / 블랙박스 협업)

에이전트들은 서로의 내부 기억(Memory), 프롬프트, 보유 도구 목록을 속속들이 들여다보지 않고도(불투명하게, Opaque) 협업합니다. 외주 회사의 내부 영업비밀을 몰라도 공식 요청서와 납품물만으로 일하는 것과 같아 보안과 독립성이 지켜집니다.

🌐

원칙 2. 검증된 기존 웹 표준 기반 (Build on Existing Standards)

새롭고 생소한 통신 규격을 억지로 만들지 않고, 전 세계 인터넷이 이미 매일 쓰고 있는 HTTP, JSON-RPC 2.0, SSE(실시간 스트리밍) 위에 세워졌습니다. 덕분에 기존 회사 서버나 방화벽에 즉시 연결됩니다.

🔐

원칙 3. 기본 내장된 보안 (Secure by Default)

실제 기업 환경에서는 아무 에이전트나 재무·인사 에이전트에게 명령을 내리면 큰일 납니다. A2A는 명함(AgentCard) 안에 기업 표준 인증(OAuth, API Key 등) 요구사항을 기본으로 명시하도록 설계되었습니다.

⏳

원칙 4. 장기 실행 작업 & 실시간 중계 (Long-Running Tasks)

0.1초 만에 끝나는 일뿐만 아니라, 몇 시간~며칠이 걸리는 심층 조사나 사람의 결재가 필요한 업무(input_required)도 지원합니다. 배달 앱처럼 작업의 진행 상태(working ➡️ completed)를 실시간으로 알려줍니다.

🎨

원칙 5. 다양한 데이터 형태 지원 (Modality Agnostic)

에이전트끼리 글자(TextPart)만 주고받는 것이 아니라, 정형화된 표/JSON 데이터(DataPart), 첨부 파일, 이미지, 음성, 영상까지 상자(Part)에 담아 교환할 수 있습니다.

비교 항목 🔌 MCP (Model Context Protocol) 🤝 A2A (Agent-to-Agent Protocol)
주도 기관 앤트로픽(Anthropic) 시작 ➡️ 오픈 생태계 구글(Google) & 50+ 파트너사 시작 ➡️ Linux Foundation
연결 방향 수직 연결 (에이전트 ↔ 도구/DB/파일) 수평 연결 (에이전트 ↔ 동료 에이전트)
상대방의 투명도 도구의 입력 변수(JSON Schema)를 정확히 알아야 호출 가능 상대 에이전트의 내부 프롬프트·도구를 몰라도(블랙박스) 자연어/데이터로 의뢰 가능
대화 방식 1회성 함수 호출 (call_tool ➡️ 즉시 결과 반환) 다회성 대화, 역질문(input_required), 장기 작업 상태 추적(Task)
핵심 구성요소 Tools, Resources, Prompts AgentCard, AgentSkill, Task, Artifact

3. A2A 프로토콜의 4대 핵심 용어와 통신 순서

A2A 코드를 읽을 때 항상 등장하는 4가지 핵심 객체만 우리말 비유로 익혀두면 모든 예제 파일이 한눈에 읽힙니다.

🪪

1. AgentCard (공식 명함)

"에이전트의 온라인 명함"
이름, 서버 주소(url), 스트리밍 가능 여부, 보유 기술(skills)을 담아 표준 주소인 /.well-known/agent-card.json에 걸어둡니다.

🏅

2. AgentSkill (보유 자격증)

"명함 뒷면의 전문 분야 목록"
내가 어떤 일을 잘하는지(설명, 태그, 질문 예시)를 적어두어 총괄 에이전트가 누구에게 일을 맡길지 판단하게 돕습니다.

🧑‍💼

3. AgentExecutor (창구 매니저)

"A2A 통역 홀 매니저"
외부에서 도착한 A2A 요청(RequestContext)을 받아 내부 에이전트를 실행하고, 진행 상황을 EventQueue로 내보냅니다.

📦

4. Task & Artifact (작업표 & 납품함)

"접수 번호표와 최종 결과물 택배"
작업 중엔 TaskState.working 상태를 알리고, 완료되면 결과물을 Artifact(납품 상자)에 포장해 건네줍니다.

🔄 A2A가 일하는 3단계 표준 순서: ① 명함 교환 ➡️ ② 작업 의뢰(Task) ➡️ ③ 결과물 납품(Artifact)

5. [실습 2] LangGraph 기반 계산 & 시간 에이전트 (포트 10001)

두 번째 실습은 LangGraph와 gemini-3.8-flash로 만든 에이전트를 A2A 서버(10001번 포트)로 포장하는 방법입니다. 계산기(calculator)와 현재 시각(get_current_info) 도구를 가지고 있습니다.

💡 왜 TaskUpdater를 사용할까요? (배달 앱 실시간 중계)

Hello World는 0.01초 만에 끝나지만, 실제 AI 에이전트는 도구를 실행하고 생각하는 데 몇 초가 걸립니다.
그래서 LangGraphAgentExecutor는 TaskUpdater를 사용해:
• 도구 실행 중일 때 ➡️ TaskState.working ("도구를 실행하는 중...")
• 추가 질문이 필요할 때 ➡️ TaskState.input_required
• 완료되었을 때 ➡️ updater.add_artifact(...) 후 updater.complete()로 깔끔하게 납품합니다!

📄 CHAP10_A2A/multi_agent/langgraph_agent/agent.py gemini-3.8-flash + LangGraph 
from langchain_google_genai import ChatGoogleGenerativeAI

class LangGraphAgent:
    def __init__(self):
        # 1. gemini-3.8-flash 모델 준비
        self.llm = ChatGoogleGenerativeAI(model='gemini-3.8-flash')
        self.tools = [calculator, get_current_info]
        self.memory = InMemorySaver()

        # 2. ResponseFormat(completed / input_required / error)으로 구조화된 응답 생성
        self.agent = create_agent(
            self.llm,
            tools=self.tools,
            system_prompt=self.SYSTEM_INSTRUCTION,
            checkpointer=self.memory,
            response_format=ResponseFormat,
        )

6. [실습 3] 순수 MCP 기반 Tavily 웹 검색 에이전트 (포트 10002)
